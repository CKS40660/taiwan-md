## #1832：順著一句推論找到 no-cors 的洞

tboydar 第二輪寫「綁 loopback 之後，spawn 端點只剩本機程序可達，CORS 已擋住非 localhost origin」。這句話 10-16 那班的回覆沒有去碰。往下追：CORS 只擋外站網頁讀回應，不擋它送出簡單 POST，而 `/api/control/resume` 與 `/api/tasks/:id/spawn` 都不讀請求內容，任何網頁用 `no-cors` 打一下 127.0.0.1:4319 就能讓排程器開始以本機身分派工。修在 `cb901d247`：CORS 中介層抽成 `docs/semiont/harvest/backend/src/http/origin-guard.ts`，寫入類請求帶著外站 Origin 一律 403，curl 與排程器不帶 Origin 所以不受影響。bun test 7 條，拿掉那條規則前三條會失敗，實際開機用 curl 打 pause 驗了四種情況。共享密鑰那條縱深建議本輪不加，理由寫在 issue 回覆裡：剩下要防的是同機的其他程序，它們本來就能以同一身分直接跑 CLI。
