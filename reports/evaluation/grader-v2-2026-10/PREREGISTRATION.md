# 第二版閱卷預先登記

> 本檔在任何第二版閱卷分身被派出之前 commit。之後判讀照本檔規則，不事後調整門檻；有偏離就在結果報告逐條寫明。

## 1. 要回答的問題

第一版（[evaluation-grader-pilot-2026-10-18](../../evaluation-grader-pilot-2026-10-18.md)）的失敗形狀：冷讀分身在八份回答裡五份說出了哲宇點名的毛病，四份仍選了有毛病的那一版。它們看得見問題，但在「想不想讀完」的整體偏好裡，把鉤子、衝突、清楚的主張擺在對人的分寸之上。

第二版的假設：**偵測交給 LLM，權衡交給一條照哲宇價值排序寫死的規則**，就能讓結果更接近他的判斷。具體改了四件事：

1. 角色從「一位讀者」改成「替創辦人預審的總編」，明說好看的稿子也可能要退。
2. 拿掉整體偏好題。改成十五題逐條檢查（[rubric.md](rubric.md)），每題答有／沒有／不確定，「有」必須逐字引用原句並給嚴重度。
3. 判決由程式照固定規則算（§4），模型不做最後的權衡。
4. 每篇各自獨立審，配對的勝負由兩篇的審稿單比出來；分身從頭到尾只看到一篇，位置偏誤從設計上消失。

這一輪要驗的是「當預審員」夠不夠格：在哲宇讀之前，把他會點名的問題標出來，同時不把他稱讚的文章標成有大問題。它**不**驗「能不能取代哲宇做最後決定」。

## 2. 審稿單的來源

十五題依 76 條哲宇編輯判斷原話整理（語料由唯讀分身從 memory、diary、LESSONS、EDITORIAL、報告撈出，分成 15 類；全文附在結果報告的證據檔）。從語料歸納的價值排序：

1. 對人公平、不拆穿受敬重的人、不公審私生活（「會炎上」「不要公審人家的私生活」都是退件理由）。
2. 公平不等於稀釋：真實的爭議可以寫，公共議題可以用矛盾當主軸（「不要一直過度弱化」「這題寫成多觀點立場議題探討矛盾型也沒問題」）。
3. 讀者感受勝過流程合規：「讀到第一個段落就不想看」可以讓三篇全綠的文章回爐。
4. 後台、查證、校正的聲音不進正文。

題目寫成通用問法，不提任何保留題文章的名字或情節。示例只來自開發題。

| 題組                          | 內容                                                                                                                                                                                                            | 用途                   | 計入通過判定 |

| 保留題（heldout）             | 哲宇批評過、沒參與題目設計的已 commit 版本，共七篇：黃崇仁第二輪、馬祖國際藝術島、外送專法、比國家還大的演算藝術 A 輪與 C 輪、國家太空中心、台灣鎢供應鏈。每篇事前對應到審稿單題號（manifest.json 的 concerns） | 量召回                 | 是           |
| 保留題修正版（heldout_fixed） | 上述各篇之後修好的版本（有的話）                                                                                                                                                                                | 量「修好後是否變好」   | 只報告       |
| 對照組（control）             | 哲宇稱讚或拿來當範本的四篇現行版：黃魚鴞、國宅與居住正義、張懸與安溥、嚴長壽                                                                                                                                    | 量誤報                 | 是           |
| 植錯題（mutant）              | 在對照組裡各植入一種錯，共六篇：A1 拆穿、A3 門面、A5 全稱否定、B1 校正句、B2 開場堆砌、B3 後設主張                                                                                                              | 量偵測                 | 是           |

保留題的限制先寫：演算藝術 A、C 兩輪是同一篇文章的前後兩版，彼此不獨立；國家太空中心那句是「原本很棒但還不夠立體」，褒貶並存；外送專法對應的是第三層（段落太長），照規則只要判決不是「可出版」就算抓到。被批評但從沒 commit 的版本（黃崇仁第一輪、蘋果西打、黃山料標題、彎彎、金曲獎 v1）不收，不拿別的版本替代。

對照組的限制先寫：嚴長壽在語料裡唯一的紀錄是 2026-04 的「還不夠好」，之後重寫過，找不到讚許原話；張懸與安溥只有「偏好參照」的標示。這兩篇的誤報照算，但結果報告要分開列。

植錯題的植入文字只存在本機，不進 git（[mutations.json](mutations.json) 記位置、類型與 sha256）。替在世者捏造私生活，即使只為測試也不該寫出來，所以 A2 不做植錯；涉及真人的植錯（A1）只用文章既有事實換成拆穿框架，不加新指控。

## 4. 判決規則（程式計算，[build.py](build.py) `judge()`）

- 引句核對：「有」的證據必須在文章裡逐字找得到（正規化空白、腳註記號與 markdown 符號後比對）。找不到的「有」不計入判決，另計入引句有效率。
- 判決：
  - 任一第一層題「有、重」→ **退件**
  - 任一第一層題「有、中」，或任一第二層題「有、重」，或兩題以上第二層「有、中或重」→ **重修**
  - 一題第二層「有、中」，或任一第三層「有、中或重」→ **小修**
  - 其他 → **可出版**
- 成對比較：先比判決等級，再依序比（第一層重、第一層中重、第二層重、第二層中重、第三層中重）的題數，少者勝；全部相同為「分不出」。

## 5. 指標與通過門檻

每個模型（Fable、Sonnet）分開算。

| 指標       | 定義                                                                         | 門檻   |
| ---------- | ---------------------------------------------------------------------------- | ------ |
| 保留題召回 | 保留題中，至少一個事前對應的題號被「有」且引句核對通過，且判決不是「可出版」 | ≥ 70%  |
| 對照組誤報 | 對照組四篇裡，被判「退件」的篇數                                             | ≤ 1    |
| 植錯偵測   | 植錯篇中，目標題被「有」、引句核對通過、且引句落在植入文字上                 | ≥ 5／6 |
| 引句有效率 | 全部「有」的引句裡，逐字找得到的比例                                         | ≥ 90%  |

四條全過，才算「第二版可以當預審員試用」。任一條不過，照實報告哪一條、差多少，不調門檻重算。

只報告、不判通過的：開發題六對的成對結果（跟第一版 Fable／Sonnet 對照時要註明開發題已被看過）、保留題修正版的判決是否比批評版好、各題的命中分布。

## 6. 執行

- 每篇每個模型各派一位全新的分身（Agent 工具，`general-purpose`，model 依序 fable 與 sonnet），只准 Read 一個提示詞檔、Write 一個輸出檔。提示詞檔用中性檔名，放在 session 暫存區，對照表在 [dispatch-map.json](dispatch-map.json)，檔名不洩漏好壞、題組或是否植錯。
- 收件時程式核對輸出檔存在且是合法 JSON；缺件或壞件照實列出，不補跑超過一次。
- 植錯篇的輸出含植入文字，收件後移到 `out/mutant/`（不進 git）。
- 成本預估：36 篇（開發 12、保留 7、修正版 7、對照 4、植錯 6）× 2 個模型，每次約 2 萬到 3 萬 token 輸入，合計約 250 萬 token。這個對話所屬帳號的週額度在 10-18 13:1x 為 31%（routine 用的另一個帳號已用滿，與本實驗無關）。

## 7. 這一輪不做的

- 不做事實查核層（§6.3 那一層），這裡只驗閱卷。
- 不看圖片與版面，只有文字。媒體類的指正（圖太少、配圖是填位圖）不在範圍內。
- 不調任何站上閘門，不改任何文章。
